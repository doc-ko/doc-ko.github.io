![Karl Oberio](./_dp.jpg)

I am a technical writer focused on developer-facing documentation: API introductions, procedural guides, and reference material that needs to stay accurate without becoming heavy.

My strongest work sits close to engineering teams. I like clarifying product behaviour, checking docs against the source material, and turning rough notes or generated output into something a developer can actually use.

I am comfortable around Git, Markdown, static sites, OpenAPI tooling, and small code changes. I would describe that as engineering fluency rather than full-time software engineering experience; the value I bring is documentation judgment with enough technical context to ask better questions.

## Current Interests

- API documentation and developer onboarding
- Documentation sites built from lightweight static tooling
- Chess and its historical cousins, including [shogi](https://lishogi.org/@/doctorkohaku)
- Linux desktop workflows
