= Homepage YAML Reference
:description: Reference for every key in src/data/homepage.yaml.

`src/data/homepage.yaml` holds the homepage copy.
The keys are specific to this site: they are not a standard format, and they exist only because `src/pages/index.astro` and the components in `src/components/` read them by name.
This page lists every key, where it appears on the page, and how its value is rendered.

== How The File Is Used

* `src/data/homepage.js` parses the YAML and exports it as `homepage`.
* `src/pages/index.astro` destructures the top-level sections and passes them to components.
* Components render the values.
Most text goes through Markdown; a few values are plain text.

If you rename a key or remove a section, the matching text disappears from the page or the build fails.
Change values freely, add or remove list items, but keep key names and nesting as documented here.

== Value Types

Markdown (inline)::
Rendered with `MarkdownInline.astro`.
Links, emphasis, and inline code work.
The result is not wrapped in a paragraph, so keep it to one line.

Markdown (block)::
Rendered with `MarkdownCopy.astro`.
Paragraphs, lists, links, emphasis, and inline code work.

Plain::
Used as-is.
No Markdown is processed.

Raw HTML is not allowed in Markdown values.

=== AI-marked text

Markdown values can mark AI-generated text the same way Markdown pages do.
See xref:customising-the-site.adoc[] for the syntax and how it looks.

* `:ai[...]` works in both inline and block Markdown values, including a `note` that explains the underline: `:ai[AInese]{note="..."}`.
* `:::ai` blocks only work in block Markdown values.
Inline values sit inside headings and labels, where a block would break the layout.
* Plain values are not processed, so `:ai[...]` would show up literally.
* An `:::ai` block needs a literal `|` scalar.
A folded `>-` scalar joins single line breaks into spaces, which would put `:::ai` on the same line as the text.
* Quote a value that starts with `:ai[`, or use a block scalar, so YAML reads it as a string.

[[email-links]]
=== Email links

The contact address never appears in `homepage.yaml`.
Link to it in one of two ways, and the site fills it in from `src/data/contact.js`:

* In a `links` list, give the item `email: true` instead of an `href`.
The `label` is the link text.
* In a Markdown value, write `:email[]` to show the address as the link text, or `:email[some words]` to use those words.
This works in inline and block values, including inside `:ai[...]`.

Do not write the address or a `mailto:` link here; see xref:customising-the-site.adoc#contact-email[] for why.

[source,yaml]
----
hero:
  lede: >-
    Apologies for the :ai[AInese]{note="Text with lines above and below it, like
    this word, was written by AI."}; I'll get round to it at some point.
  note:
    body: |-
      **This page is a stub.**

      :::ai
      A paragraph the model wrote.
      :::
----

== Top-Level Keys

[cols="1,3",options="header"]
|===
| Key | Purpose

| `meta`
| Browser title and search description.

| `hero`
| Opening section: kicker, headline, lede, status note, top links, margin note.

| `sections`
| Number, heading, and note of section 01.

| `fields`
| The four subjects drawn in the hero emblem.

| `notes`
| Status notes in section 01.
|===

== meta

[cols="1,1,3",options="header"]
|===
| Key | Type | Where it appears

| `meta.title`
| Plain
| Browser tab title.

| `meta.description`
| Plain
| Search engine description.
|===

== hero

[cols="1,1,3",options="header"]
|===
| Key | Type | Where it appears

| `hero.kicker`
| Markdown (inline)
| Small line above the headline.

| `hero.headline`
| Markdown (inline)
| Page heading (`h1`).

| `hero.lede`
| Markdown (block)
| Paragraph under the headline.

| `hero.note.label`
| Markdown (inline)
| Label on the note under the lede.

| `hero.note.notation`
| Markdown (inline)
| Monospace text beside the note label.

| `hero.note.body`
| Markdown (block)
| Text inside the note.

| `hero.links`
| List
| Row of links under the note. Each item has a plain `label` and either a plain `href` or `email: true`; see <<email-links>>.

| `hero.margin.label`
| Markdown (inline)
| Label of the margin note under the hero emblem.

| `hero.margin.body`
| Markdown (block)
| Text of that margin note.
|===

== sections

`sections` has one entry, `method`, which is section 01.
It is a section heading, rendered by `SectionHeading.astro`.

[cols="1,1,3",options="header"]
|===
| Key | Type | Where it appears

| `sections.method.number`
| Markdown (inline)
| Section number beside the heading.

| `sections.method.title`
| Markdown (inline)
| Section heading (`h2`).

| `sections.method.note`
| Markdown (block)
| Short paragraph under the heading.
|===

== fields

A list of the four subjects.
It draws the four-tile emblem in the hero.
Each item:

[cols="1,1,3",options="header"]
|===
| Key | Type | Meaning

| `icon`
| Plain
| Which drawing the tile uses: `linguistics`, `mathematics`, `logic`, or `computing`. The drawings are SVG paths in code, not text, so the YAML only names them.

| `title`
| Markdown (inline)
| Tile label.

| `description`
| Markdown (block)
| Not shown on the page at the moment.

| `accent`
| Plain
| Colour of the drawing. See <<accents>>.
|===

== notes

A list of status notes in section 01.
Each item:

[cols="1,1,3",options="header"]
|===
| Key | Type | Meaning

| `kind`
| Markdown (inline)
| Label such as "Missing". Any text works.

| `title`
| Markdown (inline)
| Note heading.

| `notation`
| Markdown (inline)
| Monospace text beside the label. Optional.

| `body`
| Markdown (block)
| Note text.
|===

The corner dot of each note is always ink, so there is no `accent`.

[[accents]]
== Accent Values

`accent` accepts `amber`, `cyan`, or `violet`.
These match the colour variables in `src/styles/tokens.css`.
`paper` is also valid for `fields`: the drawing keeps the default text colour.
Any other value, or leaving it out, falls back to the default text colour.
`notes` has no `accent`: their corner dots are always ink.
The hover animation on the hero emblem belongs to the `icon`, not the accent; see xref:customising-the-site.adoc[].

== Not In The YAML

These pieces of the homepage are fixed in code:

* Header navigation (`src/components/Navigation.astro`) and footer (`src/components/Footer.astro`).

== Adding A New Key

. Add the key to `src/data/homepage.yaml`.
. Read it in `src/pages/index.astro` or the relevant component.
. Add a row to this page, including whether it is rendered as Markdown or plain text.
