= Branch Changes
:description: What the dot-grid branch changes compared with main, and what main already holds from earlier work.

This document describes the `design/dot-grid-devices` branch compared with `main`.
It then summarises the earlier work that is already on `main`, so you can see how the site got to its current shape.

== Summary

The site is a personal blog for technical writing.
The design is a notebook page: a recycled-grey (or dark) sheet with a dot grid, and boxes and rules drawn like pen lines through the dots.
This branch builds that grid and the drawn elements, and adds a test that keeps every page on the grid.
Plans and decisions are in `.claude/plans/dot-grid-redesign.md`, and the work is tracked in issue #17.

== What This Branch Changes

=== The 24px Grid

Every line of text and every box edge sits on a multiple of 24px, which is the grid unit `--u`.
The dots in the page background mark the lines.

* The content column is a whole number of units wide, never wider than 1080px, and is one column under 680px.
* Headings and body text use whole-unit line heights.
* The text typeface is Literata, self-hosted in `public/fonts/` (regular, semibold and italic).
  `BaseLayout.astro` preloads the two upright weights.
* Boxes whose height is not known in advance (images, scrolling code blocks, display maths) are rounded up to whole units by `src/scripts/grid.js`.
  The page still works without the script; the lines below such a box just drift off the dots.

=== The Grid Check

Add `?grid` to any page address to draw the unit lines and outline every box that is off the grid in red.
`src/scripts/grid-check.js` does the measuring.

`npm run test:grid` builds the site and runs the same check on every page at phone and desktop width, in both themes, using Playwright.
A second test splices an image of odd height, a long code block and display maths into a copy of the About page, and checks that they pad out to whole units.
That copy exists only inside the test; it is not a route and does not appear in `dist/`.
The build workflow in `.github/workflows/build.yml` runs the check on every pull request.

=== Pen-Drawn Elements

`src/lib/pen.js` draws every wobbly line, hatch and highlighter end at build time.
The same seed always gives the same drawing.
The components that use it, under `src/components/`:

* `Note.astro` renders a note: a pen-drawn box in the text, or a pencil rule and dot in the margin.
  It replaces `NoteBlock.astro` and `MarginNote.astro`, which are removed.
* `DrawnEdges.astro` draws the edges of any box.
* `Dot.astro`, `PencilRule.astro` and `Highlight.astro` are the small pieces.
* `CodeBlock.astro` wraps code in a pencil bracket.
* `FieldEmblem.astro` now has hatched tiles drawn at build time and keeps its hover animations.
* `PenLoop.astro` draws a pen circle round a word; the header uses it.
* `IconHatch.astro` hatches the cell of an icon button, drawn at build time.

=== Header And Menu

The header and navigation are drawn with the same pen elements: a pen circle round the current page, and a rule under the header.
Hovering or focusing another link draws the circle in there and takes it back from the current page, so the circle seems to move.
The navigation lists Home, Blog and About; there is no Contact tab.

The theme toggle's icon turns into the other one on hover, and its cell is hatched in the tone of the theme you would switch to.
The hamburger is hatched the same way, and stays hatched while the menu is open.
Under 680px the links fold into a menu opened by the hamburger button.
`src/scripts/menu.js` runs it.
Reduced motion turns the transitions and animations off.

=== Colours And Styles

Every colour is written once in `src/styles/tokens.css` as a `light-dark(light, dark)` pair.
The red `?grid` overlay colour is one of them (`--debug`).

The styles are split under cascade layers into `tokens.css` (colours and other variables), `grid.css` (the grid, base elements and page layout), `devices.css` (notes, the code bracket, the field emblem, buttons, tags) and `pages.css` (header, footer, homepage sections).

== Already On Main

=== Light And Dark Themes

A light ("recycled grey") and a dark palette, switched by the header toggle.
The theme follows the system setting until you choose one, and `src/scripts/theme.js` remembers the choice.

=== Homepage

The homepage in `src/pages/index.astro` has a hero with a short statement, a note and a four-symbol emblem, a field section, a section of notes about the state of the site, and a closing section with links.
Most of its text is in `src/data/homepage.yaml`, loaded by `src/data/homepage.js`.
Fields accept Markdown through `src/components/MarkdownCopy.astro`, `src/components/MarkdownInline.astro` and `src/lib/homepageMarkdown.js`.
The keys are documented in xref:homepage-yaml.adoc[].

=== Site Shell And Navigation

* `src/layouts/BaseLayout.astro` handles metadata, the skip link, the header, the footer and the optional hidden page title.
* The navigation lists Home, Blog and About.
* The header logo reads `oberio.me`.
* `src/components/Footer.astro` shows the copyright line and four buttons: LinkedIn, GitHub, Repo and Docs.

=== AI-Generated Text Marking

Text can be declared AI-generated with `:ai[...]`, an `:::ai` block, or `origin: ai` in a page's frontmatter.
Marked text has a faint dashed line above and below it, AI posts in lists get the same rules on their link (the blog index also adds a small `AI` mark), and code blocks, display maths, images and notes get a cross-hatched strip with "AI" instead of the text marking.
A marked phrase can carry a note that shows on hover, tap, or keyboard focus.
`src/lib/remarkAiText.js` holds the plugin, and `src/lib/markdownPlugins.js` lists it with the other Markdown plugins.

=== Maths And Code In Posts

Posts support maths through KaTeX and syntax-highlighted code through Shiki, both following the active theme.

=== Highlights, Notes And Code Brackets In Markdown

Posts can use `:hl[...]` (or the `==...==` shorthand) for a highlight, `:::note[Label]` for a note, and every fenced code block is drawn in the pencil bracket.
`src/lib/remarkDirectives.js` holds the plugin, and `markShorthand` in `src/lib/markdownPlugins.js` sets or disables the shorthand.
`src/lib/penHtml.js` builds the drawn-edge and dot markup that these directives and the `DrawnEdges` and `Dot` components share.

=== Contact Email Hidden From Scrapers

The contact address is stored backwards in `src/data/contact.js` and turned back round by `src/scripts/email.js` in the browser, so it does not appear readably in the repo or the built pages.
The homepage and About page link to it through `EmailLink.astro`, `email: true` in `homepage.yaml` lists, or `:email[]` in Markdown.
See xref:customising-the-site.adoc#contact-email[].

=== Domain And Deployment

The site publishes at `oberio.me`.
`astro.config.mjs` sets `site` to `https://oberio.me`, and `public/CNAME` names the same domain.
`.github/workflows/deploy.yml` deploys to GitHub Pages.
The footer Docs button still points at `docs.docko.dev`.

=== Removed Content

The site no longer holds documentation work samples.
The blog and tag pages are still there, ready for new posts; `/blog/` shows "No posts yet." while it is empty.

=== Local Agent Tooling

The repo includes the `agent-browser` skill under `.agents/skills/`, recorded in `skills-lock.json`, and agent instructions in `AGENTS.md`.
None of it affects the public website.

== What To Watch

* The homepage data object shape matters.
  Components expect fields like `hero.links`, `fields` and `notes`.
* Anything whose height is not a whole number of 24px units pushes every line below it off the dots.
  Run `npm run test:grid` after layout changes.
* Markdown pages should include `tags`; the tag pages depend on frontmatter tags.
* External links in `LinkButton.astro` automatically open in a new tab when the URL starts with `http`.
* The styles are shared by every page, so a broad selector in `src/styles/grid.css` can affect many pages.
